# AI 商用图片模板网站：完整产品规划

> 文档状态：V1.0 产品基线  
> 产品对象：不会写提示词、缺少设计能力的中小实体店主、电商卖家及个体经营者  
> 核心承诺：不需要学习提示词，选择一个喜欢的模板，替换自己的商品与文案，即可获得可直接发布的商用图片。

## 1. 项目基础与产品判断

### 1.1 现有项目可复用能力

当前项目已经具备一条可工作的 AI 生图闭环：

- 微信小程序前台：模板浏览、图生图/文生图表单、生成等待、结果保存、历史记录、分享与反馈。
- 模板配置：模板分组、首页图、详情图、动态输入字段、提示词占位符、图片上传数、模型、兜底模型、消耗积分、草稿与发布。
- 后台调试：填写动态字段或上传测试图片，实时编译提示词，提交异步任务，轮询状态，展示结果、模型、耗时与兜底情况。
- 生成服务：异步任务、主/备模型路由、不同 Provider 适配、失败退款、生成历史、图片云存储。
- 账户与商业化基础：用户积分、积分流水、充值与支付相关能力。

因此，新网站不需要从零验证“能否生成图片”，真正需要产品化的是：模板内容体系、外部用户的低门槛编辑体验、品牌资产复用、结果可控性、商业化和运营闭环。

### 1.2 当前能力与外部产品之间的差距

| 当前内部/小程序能力 | 面向外部用户需要升级为 |
| --- | --- |
| 模板卡片 + 简单分组 | 可搜索、可筛选、按行业/用途/节日组织的模板市场 |
| 动态文本字段 | 有示例、有解释、有默认值、有类型约束的“业务信息表单” |
| 上传参考图 | 商品主体识别、去背、裁切建议、清晰度检查和素材管理 |
| 编译提示词 | 对用户完全隐藏，只呈现自然语言的可控选项 |
| 单次调试生成 | 可回退、可复用、可生成变体的创作工作台 |
| 单张结果 | 结果对比、再次生成、局部修改、改尺寸、下载与归档 |
| 星光积分 | 套餐、订阅、用量说明、失败不扣费和账单 |
| 技术型后台 | 模板生产、审核、灰度、数据分析和质量运营后台 |

### 1.3 产品定位

产品不是通用 AI 绘画工具，也不是专业设计软件，而是“以模板为入口的商用图片生成工具”。

一句话定位：

> 面向小商家和电商卖家的 AI 商图助手，把复杂提示词封装进经过验证的模板，让用户只替换商品、品牌和活动信息，就能生成海报、宣传单与电商图。

产品原则：

1. 模板优先：用户先看结果风格，再决定填写什么。
2. 业务语言优先：界面只出现“商品名、卖点、活动价”等词，不向用户暴露模型、Provider、Prompt。
3. 所见即所得：填写信息时同步展示内容摘要、版式安全提示和预期效果。
4. 先成功再高级：默认选项必须能生成可用结果，高级参数后置。
5. 可追溯、可恢复：生成任务、费用、版本、输入和结果均有记录。
6. 模板与模型解耦：模板定义业务和视觉意图，模型路由由平台策略决定。

## 2. 用户与核心场景

### 2.1 核心用户

#### A. 线下实体店主

- 行业：餐饮、烘焙、水果、生鲜、美容美发、健身、教育培训、宠物、零售。
- 高频任务：节日海报、今日特价、新品上市、开业促销、朋友圈宣传图、门店价目表。
- 痛点：没有设计师、时间紧、不会写提示词、手机素材杂乱、文案和图片经常不协调。

#### B. 中小电商卖家

- 渠道：淘宝、拼多多、抖音、小红书、视频号、私域社群。
- 高频任务：商品主图、场景图、详情页卖点图、促销图、尺寸适配、同款多风格测试。
- 痛点：出图量大、平台尺寸不同、拍摄成本高、需要快速做多版本测试。

#### C. 个体营销从业者

- 角色：微商、团购团长、自由职业者、门店代运营。
- 高频任务：批量为不同客户替换品牌、电话、地址、价格与二维码。
- 痛点：重复劳动多，希望保存品牌资料并快速复用。

### 2.2 首期优先场景

MVP 聚焦高频、结构清晰、结果容易判断的四类内容：

1. 节日/节气促销海报。
2. 新品上市与门店活动宣传单。
3. 电商商品主图与商品场景图。
4. 社交媒体方图、竖版推广图。

首期暂不承诺：专业印刷排版、多页画册、自由图层设计、复杂 Logo 生成、视频生成、长篇电商详情页自动编排。这些能力会显著扩大编辑器复杂度，应在模板生成闭环验证后逐步增加。

## 3. 产品目标与成功标准

### 3.1 北极星指标

**每周成功导出的有效商用图片数。**

“有效”定义为：生成成功后被下载、分享，或进入后续改版流程的图片。它比单纯生成次数更能反映产品价值。

### 3.2 MVP 核心指标

| 环节 | 指标 | 建议目标 |
| --- | --- | --- |
| 激活 | 新用户首次成功生成率 | ≥ 55% |
| 效率 | 从选模板到提交生成的中位时长 | ≤ 3 分钟 |
| 稳定 | 平台侧任务成功率 | ≥ 95% |
| 质量 | 首次结果下载/继续编辑率 | ≥ 35% |
| 留存 | 新用户 7 日内再次生成率 | ≥ 20% |
| 模板 | Top 20 模板贡献生成量占比 | 用于识别有效供给，不设硬目标 |
| 商业 | 付费用户月度有效导出成本 | 可覆盖模型、存储和支付成本并保留毛利 |

质量指标必须按模板、模型、行业、输入类型和尺寸分别观测，避免总平均掩盖问题。

## 5. 核心用户旅程

### 5.1 首次用户最短路径

1. 首页直接看到按真实业务场景组织的模板，不强制先登录。
2. 用户点击模板，查看示例图、适用场景、需要准备的内容、预计消耗和预计时长。
3. 点击“使用此模板”，进入三栏式工作台。
4. 左栏填写信息/上传商品，中央实时显示模板预览，右栏展示样式选项与生成设置。
5. 未登录用户完成填写后，在提交生成时进行手机号/微信扫码登录，避免过早打断。
6. 生成任务进入队列；用户可停留等待，也可离开页面，任务中心持续显示状态。
7. 结果页并排展示 2—4 个候选结果；用户可下载、再生成一组、换风格、改文案、改尺寸或收藏。
8. 首次成功后提示保存品牌资料，下次自动填充。

### 5.2 老用户复用路径

1. 从“我的作品”复制上一次项目，或从首页选择模板。
2. 自动带入默认品牌资料与常用素材。
3. 仅修改本次活动信息。
4. 生成并导出多个平台尺寸。

### 5.3 失败与恢复路径

- 生成中断：保留填写内容，自动重试一次；超过阈值后提供“重新生成”并明确不扣费。
- 模型失败：后端自动切换兜底模型，用户只看到“正在切换生成线路”。
- 内容不合规：指出具体字段或素材问题，允许原地修改，不清空表单。
- 页面关闭：任务继续执行，完成后通过站内消息及可选微信通知提醒。
- 结果不满意：区分“换一批”“保持构图改文案”“保持商品换背景”“反馈问题”，为后续模型评测积累结构化数据。

## 6. 核心功能规划

### 6.1 模板发现

P0：

- 首页场景入口：做海报、做电商图、做宣传单、做社交媒体图。
- 行业、用途、节日、比例、是否需要上传商品等多维筛选。
- 搜索支持业务词和同义词，如“促销/打折/优惠”“主图/商品图”。
- 模板卡展示示例、用途、比例、所需素材、生成成本和热度。
- 收藏、最近使用、相似模板。
- 模板详情展示 3—6 个真实示例和“需要准备什么”。

P1：

- 基于行业、历史和品牌资料的个性化推荐。
- 专题页与节日运营日历。
- “上传一张参考图找相似模板”。

### 6.2 模板化创作工作台

工作台采用桌面端三栏、移动端分步结构：

- 左侧“替换内容”：业务字段、商品素材、品牌资料。
- 中央“效果预览”：模板示意、结果对比、缩放和版本切换。
- 右侧“样式设置”：比例、风格强度、色调、背景偏好和输出质量。

P0 字段组件：

- 单行文本、长文本、数字/价格、日期、单选、颜色、图片上传、Logo、二维码、开关。
- 字段包含标题、业务解释、示例、默认值、必填、长度、格式校验和敏感词提示。
- 自动保存草稿；切换模板时询问是否沿用已填内容。
- 品牌资料一键填充。
- 模板提示词完全隐藏；必要时只提供“创意要求”可选补充框。

P1 增强：

- 商品自动去背、背景清理与主体质量检测。
- 品牌色提取、文案智能缩短、卖点润色。
- 多商品批量生成和 CSV 导入。
- 保持主体、保持版式、仅改文案/背景等受控重绘。

### 6.3 生成任务与结果

P0：

- 创建任务后立即持久化，不依赖页面常驻。
- 队列状态：等待、生成中、处理中、成功、部分成功、失败、已取消。
- 默认生成 2 张候选图；成本较高时允许运营按模板配置为 1 张。
- 结果对比、单张放大、下载、收藏、删除、再生成。
- 下载前可选择 JPG/PNG 与适合的平台尺寸。
- 生成失败不扣费；部分成功按实际可用结果计费或由运营规则决定。
- 每次结果保留模板版本、模型路由版本、用户输入快照和成本记录。

P1：

- 一键生成同风格横版/方图/竖版套图。
- 局部重绘、扩图、擦除替换、高清放大。
- 文字后处理：当模型中文字不稳定时，采用“AI 生成底图 + 稳定排版层”混合方案。
- 可分享项目链接，并控制有效期和下载权限。

### 6.4 我的作品与品牌资料

P0：

- 按时间、模板、用途、状态筛选作品。
- 项目概念：一次营销任务包含输入、多个生成版本和多个导出文件。
- 自动保存最近输入，支持复制项目。
- 品牌资料包括品牌名、Logo、主辅色、口号、地址、电话、二维码。
- 单用户首期支持一个默认品牌档案，数据结构预留多品牌。

P1：

- 多品牌、多门店和团队空间。
- 商品素材库、常用活动文案库。
- 团队成员、角色和共享文件夹。

### 6.5 账户与商业化

建议首期采用“免费体验额度 + 点数包”，验证付费后再加入订阅：

- 新用户获得少量不可提现体验点。
- 普通生成、高清导出、批量尺寸、局部重绘分别定价。
- 生成前显示预计消耗；任务成功后才确认扣费。
- 余额、充值、消耗、退款均可追溯。
- 套餐页使用业务语言解释“可生成约多少张”，同时注明实际消耗可能因功能不同而变化。

后续订阅分层建议：

- 免费版：低额度、标准队列、基础模板。
- 个体版：月度额度、高清导出、完整模板库、品牌资料。
- 商家版：多品牌、批量生成、商业授权凭证、优先队列。
- 团队版：成员协作、审批、共享资产、统一账单。

避免永久无限量套餐；AI 成本随模型和输出规格变化，必须以内部成本单位与用户点数解耦。

## 7. 模板产品体系

### 7.1 模板分类模型

模板不能只依赖单一“分组”，建议建立多维标签：

- 行业：餐饮、烘焙、零售、美业、教育、宠物、服饰、家居等。
- 用途：促销海报、上新、主图、场景图、宣传单、菜单、社媒封面。
- 营销节点：节日、节气、开业、周年、新品、清仓、团购。
- 渠道：朋友圈、小红书、抖音、淘宝、拼多多、线下打印。
- 比例：1:1、3:4、4:5、9:16、16:9、A4 等。
- 输入要求：纯文字、单商品、多商品、人物、门店、Logo、二维码。
- 风格：简约、高级、国潮、清新、可爱、烟火气、科技感。

### 7.2 模板定义升级

现有 `ai_features` 可作为迁移源，但网站版应逐步升级为以下结构：

```text
Template
├─ identity: id、名称、描述、封面、示例集
├─ taxonomy: 行业、用途、渠道、节日、风格、标签
├─ input_schema: 字段组件、校验、默认值、示例、素材要求
├─ composition: 提示词模板、负向约束、版式意图、安全区
├─ output_schema: 比例、尺寸、格式、候选数、后处理流程
├─ model_policy: 能力要求、首选路由、兜底路由、超时与重试
├─ pricing_policy: 基础成本、高清/批量附加成本
├─ lifecycle: 草稿、测试、审核、灰度、发布、下线
└─ version: 模板版本、变更记录、评测结果
```

关键设计：

- 模板与展示位置是多对多关系，不把分类写死在模板上。
- 模板版本发布后不可原地覆盖；已有作品始终能追溯到历史版本。
- Prompt、模型配置与用户输入快照分开存储。
- 用户端字段使用稳定 `key`，字段标题可修改但不能随意更换 key。
- 支持条件字段，例如“开启活动价后才显示原价/现价”。
- 支持计算字段，例如自动生成折扣比例。

### 7.3 模板生产与质量门槛

每个模板发布前必须经过：

1. 输入完整性检查。
2. 至少 5 组不同业务数据测试。
3. 商品主体保持、文字正确性、构图、品牌露出和安全合规评分。
4. 主模型和兜底模型测试。
5. 各目标比例测试。
6. 成本与耗时评估。
7. 移动端和桌面端表单预览。

发布状态建议：草稿 → 待测试 → 待审核 → 灰度 → 已发布 → 已下线。灰度期限制流量，达到成功率与下载率门槛后放量。

## 8. 运营后台规划

### 8.1 模板编辑器

- 基础信息、分类标签、示例图和适用说明。
- 可视化字段编排，支持字段类型、条件、校验、默认值和示例。
- Prompt 变量插入、缺失变量检测和未使用字段检测。
- 输出比例、候选数、后处理和定价配置。
- 主/备模型策略不直接绑定单一 Provider，可选择“能力策略”或明确路由。
- 保存草稿、版本差异、预览、灰度和回滚。

### 8.2 调试中心

现有 `FeatureDebugPanel` 应升级为独立调试中心：

- 多组测试用例保存与重复执行。
- 同一输入对比不同模型、不同 Prompt 版本。
- 显示结果、耗时、模型成本、失败阶段和兜底情况。
- 结构化人工评分：主体保持、文字正确、构图、美观、商用可用性。
- 设定发布门槛，失败用例阻止模板上线。
- 调试任务与真实用户任务隔离，不计用户余额但计入内部成本。

### 8.3 运营与风控

- 模板曝光、点击、开始填写、提交、成功、下载、复用漏斗。
- 任务失败按 Provider、模型、模板和错误类型聚合告警。
- 用户投诉、违规内容、退款和封禁处理。
- 节日专题排期、模板置顶、推荐位配置。
- RBAC：超级管理员、模板编辑、审核员、运营、客服、财务、只读分析。
- 所有敏感配置、退款、封禁、模板发布保留审计日志。

## 9. 交互与 UI 方向

### 9.1 视觉定位

目标用户偏好应是“可靠、清楚、有生意感”，而不是极客式 AI 控制台，也不是过度艺术化的设计师工具。

建议风格：

- 基础背景使用暖白或浅米灰，降低长时间操作疲劳。
- 主色采用有活力但可信的橙红/珊瑚色，强调“生意增长”和行动；深墨色负责文字与专业感。
- 图片模板是页面主角，UI 控件保持克制。
- 圆角 10—14px，轻阴影，避免大量玻璃拟态和高饱和渐变。
- 中文字体优先使用系统黑体；数字价格可加强字重，不使用难读的装饰字体。
- 所有按钮使用结果导向文案：如“生成 2 张效果图”，而不是“提交”。

建议基础色板：

- 品牌主色：`#F25C3D`
- 主色悬停：`#DD472B`
- 深色文字：`#202124`
- 次级文字：`#667085`
- 页面背景：`#F7F5F2`
- 卡片背景：`#FFFFFF`
- 成功：`#168A5B`
- 警告：`#D98A00`
- 错误：`#C83B32`

### 9.2 易用性规则

- 首页首屏直接回答“我能做什么”，不以 AI 模型能力开场。
- 每屏只有一个主要动作。
- 表单字段不超过 6 个时单页完成；超过 6 个时按“商品—活动—品牌—样式”分组。
- 高级设置默认收起，系统提供推荐值。
- 上传区明确展示正确与错误示例。
- 生成前给出内容摘要和预计点数，不展示编译后的 Prompt。
- 生成中显示可离开提示，不制造虚假百分比。
- 结果页把“下载”作为主动作，“再生成”作为次动作。
- 所有颜色状态同时配合文字/图标，满足色弱用户识别。
- 关键流程支持键盘操作、焦点状态和基本屏幕阅读器语义。

### 9.3 响应式策略

- 桌面端：三栏工作台，适合电商卖家批量工作。
- 平板端：左侧表单 + 右侧预览，样式设置抽屉化。
- 手机端：模板详情 → 填写内容 → 确认 → 结果的分步流程；不强行缩小桌面编辑器。

## 10. 技术与数据架构建议

### 10.1 领域拆分

```text
Web/BFF API
├─ Identity：用户、组织、角色、登录
├─ Template：模板、版本、分类、发布
├─ Asset：上传、品牌资产、商品素材、导出文件
├─ Generation：任务编排、重试、状态、结果
├─ Model Gateway：模型能力、路由、Provider 适配、成本
├─ Billing：点数、套餐、订单、扣费、退款
├─ Moderation：输入输出审核、投诉
├─ Analytics：事件、漏斗、质量评测
└─ Notification：站内、微信、邮件（后续）
```

首期可以继续使用 CloudBase，避免过早微服务化；但代码和数据边界应按上述领域拆开。云函数应从当前“单个大入口按 action 分发”逐步拆成清晰模块，生成执行器保持统一接口。

### 10.2 生成状态机

```text
draft → validating → queued → running → post_processing → succeeded
                                  ├─ retrying ────────────────┘
                                  ├─ partially_succeeded
                                  ├─ failed_refunded
                                  └─ cancelled_refunded
```

要求：

- 创建任务必须幂等，避免重复点击造成重复扣费。
- 扣费采用预占 → 成功确认 → 失败释放，而不是分散在多个函数里手工补偿。
- Worker 通过租约/锁认领任务，防止重复执行。
- Provider 请求记录统一 trace ID，日志中不得暴露 API Key 和完整敏感输入。
- 长任务使用队列或定时触发机制，不依赖前端轮询触发 Worker。
- 用户轮询只是读状态；后台执行与浏览器生命周期彻底解耦。

### 10.3 模型网关

模板只声明能力需求，例如：

- text_to_image / image_to_image
- preserve_subject
- render_chinese_text
- supported_ratios
- max_input_images
- output_quality

模型网关根据成功率、成本、延迟、健康状态和灰度策略选择具体模型。保留显式锁定模型能力供调试和特殊模板使用。

Provider 适配层统一输入输出：

```text
generate(request) -> job/result
poll(upstreamJobId) -> status/result
normalizeError(error) -> category/retryable/userMessage
estimateCost(request) -> internalCost
```

### 10.4 建议核心数据实体

- users、organizations、memberships
- brand_profiles、brand_assets、product_assets
- templates、template_versions、template_inputs、template_placements、template_test_cases
- projects、project_versions
- generation_jobs、generation_attempts、generation_results
- model_capabilities、model_routes、provider_health
- wallets、credit_ledger、plans、subscriptions、orders
- moderation_records、feedbacks、audit_logs
- analytics_events、template_daily_metrics

所有余额变化使用只追加的 ledger，不直接覆盖余额且不留依据。图片存储记录归属、用途、保留期限和删除状态。

### 10.5 与现有项目的迁移策略

1. 保留现有 `ai_features` 读取兼容层，将其映射为 Template V1。
2. 新建模板版本、分类关联和测试用例数据，不直接破坏小程序字段。
3. 复用 `generationWorker` 和 Provider 执行器，但在外层加入统一任务协议与模型路由。
4. 网站账户与微信 OpenID 解耦，建立统一 userId，并把 OpenID 作为登录身份之一。
5. 积分系统迁移为统一账本，兼容现有星光余额。
6. 小程序与网站共用模板和任务底座，各自保留适配层。
7. 后台逐模块替换，避免一次性重写导致线上模板无法维护。

## 11. 安全、合规与版权

- 上传前明确用户需拥有商品图、人物图、Logo 和字体的使用权。
- 输入和输出接入内容安全审核；对人物、商标、医疗功效、虚假促销等高风险场景增加提示。
- 人脸素材提供明确授权说明和删除入口。
- API Key 仅保存在服务端密钥系统，不进入前端和普通数据库响应。
- 原始上传、生成结果和日志设置不同保留周期；支持用户彻底删除。
- 下载页提供生成记录与必要的商业使用说明，但不做超出模型供应商条款的版权保证。
- 支付、账单、退款和发票能力按实际经营主体及上线地区的法规落实。
- 上线前单独完成隐私政策、用户协议、AI 生成内容标识和第三方模型条款审查。

## 12. 数据埋点与实验

核心事件：

```text
home_view
template_impression / template_click / template_favorite
template_use_start
input_started / input_validation_failed
asset_upload_started / asset_upload_failed
generation_submitted / generation_succeeded / generation_failed
result_selected / regenerate_clicked / resize_clicked
download_started / download_succeeded
brand_profile_saved
paywall_viewed / purchase_started / purchase_succeeded
feedback_submitted
```

公共属性包括 userId、sessionId、templateId、templateVersion、projectId、industry、useCase、ratio、modelRoute、generationId、source 和 experimentId。禁止把完整用户文案、图片 URL 或敏感个人信息直接写入分析系统。

首批实验：

1. 首页按“用途”还是按“行业”作为第一入口。
2. 生成 1 张与 2 张候选图对首次下载率和成本的影响。
3. 先登录与提交生成时登录对完成率的影响。
4. 模板详情是否展示“需要准备的内容”对表单放弃率的影响。
5. 品牌资料自动填充对复用率的影响。

## 13. 分阶段路线图

### 阶段 0：产品与技术基线（1—2 周）

- 确认品牌名、上线域名、经营主体和支付方案。
- 从现有数据导出模板、模型、任务和积分字段字典。
- 选择 20—30 个高潜模板，建立标准测试用例。
- 确定统一 userId、模板版本和账本迁移方案。
- 产出关键页面线框与视觉基线。

退出条件：关键实体、核心流程、MVP 模板清单和技术迁移方案评审通过。

### 阶段 1：MVP 闭环（建议 6—8 周）

- 响应式官网与模板中心。
- 登录、用户工作区、品牌资料基础版。
- 模板详情与业务字段表单。
- 图片上传、生成任务、结果对比与下载。
- 我的作品与任务中心。
- 免费额度、点数余额和基础充值。
- 模板后台升级：分类、字段、草稿、调试、发布。
- 基础埋点、错误监控、内容审核与失败退款。

退出条件：目标模板成功率 ≥ 95%，核心流程无阻断级问题，真实种子用户能独立完成首次生成与下载。

### 阶段 2：可用性与增长（4—6 周）

- 搜索推荐、专题页、收藏与相似模板。
- 多版本对比、生成变体、多尺寸套图。
- 商品去背、素材质量检测、文案辅助。
- 套餐订阅、优惠与邀请机制。
- 模板漏斗、模型质量和成本分析后台。
- 微信通知与召回。

退出条件：7 日复用、付费转化和单位生成毛利达到内部目标。

### 阶段 3：专业化与规模化

- 多品牌、多门店、团队协作。
- 批量商品/CSV 生成。
- 混合排版引擎，解决中文文字稳定性与品牌规范问题。
- 开放模板作者/代运营协作机制。
- API 与第三方电商、素材库、商品系统集成。
- 多地域部署、成本智能路由和更细粒度风控。

## 15. MVP 验收场景

1. 新用户可在不理解提示词和模型的前提下，选择节日海报模板，填写品牌名、品类、主文案并成功下载图片。
2. 电商用户可上传一张商品图，生成保持商品主体的场景主图。
3. 用户关闭页面后任务继续，重新登录可查看结果。
4. 任务失败不产生实际扣费，账本记录可审计。
5. 用户可复制历史项目，仅替换活动信息后重新生成。
6. 运营人员可创建字段化模板、保存草稿、用测试用例调试、灰度发布并回滚。
7. 管理员可定位一次失败任务的模板版本、模型尝试、耗时、错误类别和退款记录。
8. 关键流程在桌面和手机浏览器均可独立完成。

## 16. 主要风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| AI 对中文文字渲染不稳定 | 海报不可商用 | 首期选短文案模板；逐步使用底图生成 + 稳定文字排版层 |
| 商品主体被改变 | 电商用户失去信任 | 模板标记主体保持能力；加入相似度评测与专用模型路由 |
| Provider 波动 | 失败率与等待时间升高 | 主备路由、健康检查、熔断、可重试错误分类 |
| 模板多但质量低 | 用户选择困难、结果不可控 | 少而精上线；测试集、灰度、按下载率淘汰 |
| 成本失控 | 毛利为负 | 内部成本计量、候选数配置、队列分级、动态路由 |
| 网站变成复杂设计工具 | 偏离目标用户 | 坚持模板 + 业务字段；高级编辑能力逐层开放 |
| 小程序账户无法顺滑迁移 | 用户资产割裂 | 统一 userId，多身份绑定，明确余额迁移规则 |
| 用户素材与生成内容合规问题 | 投诉或监管风险 | 授权声明、审核、举报、删除、日志和人工复核机制 |

## 17. 当前建议的产品决策

1. MVP 以“节日促销海报 + 电商商品图”为双核心，不同时扩展到所有设计品类。
2. 用户端不展示实际 Prompt、模型名和 Provider；这些只属于运营调试后台。
3. 默认生成 2 个候选结果，但允许按模板成本配置。
4. 首期继续使用 CloudBase 与现有 Worker，新增网站 BFF 和清晰领域模块，不立刻全面重写。
5. 先建立模板版本和质量评测，再大规模生产模板。
6. 先采用免费额度 + 点数包，验证复购后再推出订阅。
7. 将品牌资料与项目历史列为 P0，而不是只做一次性生成器；这是提高复用率的关键。
8. 中文海报的长期方向应是 AI 生成视觉底图与确定性文字排版结合，而不是完全依赖模型画出准确文字。

## 18. 下一步交付物

在进入开发前，建议按顺序补齐：

1. 《MVP PRD》：逐页功能、规则、异常状态与验收标准。
2. 《信息架构与用户流程图》：桌面/移动端核心路径。
3. 《低保真线框》：首页、模板中心、模板详情、工作台、结果、作品、品牌资料、套餐。
4. 《设计系统与高保真 UI》：颜色、字体、组件、响应式规范。
5. 《技术架构与迁移设计》：账户、模板版本、任务、账本和现有数据兼容。
6. 《数据库/API 契约》：实体、状态机、接口与错误码。
7. 《迭代任务拆分》：按可演示垂直切片排期，而不是按前后端分散开发。
