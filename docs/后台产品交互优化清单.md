# 后台产品与交互体验优化清单

> 范围：仅「产品与交互体验」，不含安全漏洞（安全见《后台架构优化方案.md》）。
> 结论：后台的功能骨架是完整的，但**信息架构、表单编辑、列表交互、文案术语**四块都在「能用」以下水平——这是运营「不愿打开、容易点错、改完没把握」的根源。

---

## 一、信息架构（IA）——导航与命名

### 1.1 落地页选错了

默认标签页是 `models`（模型）——这是使用频率最低、最技术化的模块。运营每天打开后台，第一眼看到的是「模型密钥表」，而不是他们真正要维护的「模板」或要看的「数据」。

**改法**：落地页改为「模板」（或新建「运营概览」），模型收进「系统配置」二级菜单。

### 1.2 导航用技术黑话，不是业务语言

| 现在 | 运营实际理解 | 建议 |
|------|------------|------|
| 模型 | 生图服务商配置 | 模型与路由（收进系统） |
| 标签 | 分组 | 分组 / 分类 |
| 图片 | 图片素材 | 素材中心 |
| 卡片 | 生图模板 | **模板** |
| 用户 | 用户 | 用户 |
| 设置 | 管理员+改密码 | 系统设置 |

### 1.3 缺少「运营概览」

`Dashboard` 组件其实只是 tab 容器，没有真正的看板。生成量、成功率、失败率、成本、收入、活跃用户这些运营最关心的数字，后台一个都看不到。

## 二、表单编辑体验（模板编辑器是重灾区）

### 2.1 20+ 字段平铺，无分组无折叠

「卡片」编辑器把以下字段**全部平铺**在 3 列网格里：名称、归属配置、模型、兜底模型、图片比例、模板类型、网站可选比例、图片目录、首页图、详情图、上传数、星光消耗、高清打印、夯数量、拉数量、状态、排序、标签、动态字段、提示词、调试面板。

没有任何「基础信息 / 内容与字段 / 模型与路由 / 高级」分组，高级项也不折叠。运营想改个名称，要在一屏里扫过「兜底模型、resolution_type、hang_count」这些技术字段。

**改法**（对齐 `WEB_PRODUCT_PLAN.md` 9.2 的「字段分组 + 高级默认收起」原则）：
- 分区：① 基础信息（名称、归属、封面、状态）② 内容与字段（提示词 + 动态字段）③ 模型与路由（折叠，默认收起）④ 定价与排序 ⑤ 预览与调试
- 高级技术字段（兜底模型、size、ratio）折叠进「模型与路由」。

### 2.2 技术字段直接暴露给运营

`model_call_id`、`fallback_model_call_id`、`base_url`、`ratio`、`resolution_type`、`provider` 全是底层字段，运营看不懂也不需要懂。产品原则是「业务语言优先，模型路由由平台策略决定」。

**改法**：模型选择改为「能力策略」下拉（如「文生图 · 保持主体 · 支持中文文字」），底层 Provider 映射隐藏在配置里。

### 2.3 状态用裸数字输入框

模型/标签/图片/卡片的 `status` 都是 `<NumberInput>`，运营要记住「1=上架、0=下架」。而且三个面板对同一概念表现不一致：模型列表显示裸数字、标签列表显示裸数字、卡片列表才显示「草稿/已发布」。

**改法**：统一为「上架 / 下架」开关或标签（带颜色），列表内可直接切换，并支持按状态筛选。

### 2.4 排序靠猜数字

`sort` 是 `<NumberInput>`，没有拖拽、没有「上移/下移」。运营调整首页顺序只能凭感觉填数字，填错互相顶。

**改法**：行内拖拽排序，或「上移/下移」按钮。

### 2.5 「夯数量 / 拉数量」是无文档黑话

`hang_count`、`la_count` 是增长黑客计数（疑似「点赞/拉新」类数据），但界面叫「夯数量/拉数量」，没有任何解释，列头直接叫「夯」「拉」。

**改法**：要么改业务名并加 tooltip 说明，要么直接隐藏（这两个字段若未用于排序，就应从运营视图移除）。

### 2.6 无必填标记、无校验提示

表单没有必填星号、没有校验规则提示，用户点保存才收到后端报错。

### 2.7 无「预览」，改了没把握

编辑卡片看不到小程序/网站端实际效果，唯一验证手段是「调试生成」跑一张图。运营改完提示词，完全不知道首页卡片、详情页长什么样。

**改法**：右侧加实时预览（卡片封面 + 详情页 + 表单在移动端的呈现），与 `web-app` 的 `template-visual` 组件复用。

### 2.8 草稿/发布是二态，改了即覆盖

只有「草稿 → 已发布」两态，发布即全量、无版本、无回滚、无灰度。改错一个字，只能靠「调试生成」慢慢试。

## 三、数据列表与表格体验

### 3.1 全模块无搜索

模型/标签/图片/卡片/用户**没有任何关键词搜索**，只有图片面板有「目录筛选 + 模板筛选」下拉、标签/卡片有「专区」切换。找一条数据只能翻页。

**改法**：所有列表加关键词搜索 + 状态筛选 + 时间范围。

### 3.2 分页只有「上一页/下一页」

`DataTable` 只提供「上一页/下一页 + 每页条数」，没有跳页、没有「第 X–Y 条 / 共 N 条」、没有总数页码。数据几百条后翻页极痛苦。

**改法**：补页码器 + 跳页输入 + 「共 N 条，当前显示 X–Y」。

### 3.3 图片表 13 列，横向滚动严重

图片面板表格有 13 列（预览、名称、目录、对象路径、用途、图片类型、生图模板、使用模型、生成用户、云存储时间、URL、操作），`min-width: 860px` 强制横向滚动。

**改法**：列优先级分层——主列（预览、名称、用途、模板）常驻，技术列（对象路径、使用模型、生成用户 OpenID）收进「详情抽屉」或折叠列。

### 3.4 用户表信息太少

用户只有「OpenID、星光、最近原因、时间」四列，看不到用户是谁、生成过什么、是否有投诉。「调整」按钮只填 OpenID，不跳详情。

**改法**：加用户详情抽屉（生成历史、积分流水、投诉记录、封禁状态）。

### 3.5 无批量操作（图片除外）

图片面板有批量下载/删除，但模板、模型、标签没有批量上下架、批量改排序。

## 四、交互反馈与状态

### 4.1 `window.confirm` / `window.alert` 滥用

删除、批量删除、强制删除、图片下载全部用**原生浏览器弹窗**。样式割裂、无法统一、无法做「输入名称确认」这类防误触。

**改法**：统一 Dialog 组件；危险操作（删除模板、删管理员）要求输入名称二次确认。

### 4.2 操作成功无 Toast

除「卡片」有 `featureMessage`，其余面板保存/删除成功后只有静默 reload，用户不知道是否成功。

**改法**：全局 Toast（成功/失败/进度）。

### 4.3 批量删除是串行循环，无进度

`removeSelected` 用 `for...await` 逐个删，删 100 张会卡很久，中途失败无提示、无法恢复。

**改法**：后端提供批量删除接口 + 前端进度条 + 失败清单。

### 4.4 批量下载逐个触发，会被拦截

`downloadSelected` 每个文件间隔 250ms 创建 `<a>` 触发下载，浏览器会拦截多文件下载。

**改法**：后端打包 zip 一次性下载。

### 4.5 加载遮罩覆盖全表，翻页闪烁

`loading-mask` 盖住整张表，翻页时白屏闪烁，无骨架屏。

**改法**：骨架屏或行级 loading。

### 4.6 调试生成轮询固定 5 秒、无超时

`setInterval(poll, 5000)` 无超时上限、无手动刷新。

**改法**：加超时提示 + 「重新查询」按钮 + 展示任务在服务端的真实阶段。

## 五、文案与术语

- **中英混杂**：「FileID」「Base URL」「分辨率」「图片比例」等。
- **状态词不一致**：同一 `status`，模型列表显示数字、卡片列表显示「草稿/已发布」。
- **英文报错直出**：`Fallback provider ... is not compatible with text-to-image...` 直接给运营看英文。
- **「发布到小程序」文案过时**：现在还有 `web-app` 网站端，文案没提网站。

---

## 六、视觉与响应式

- **无暗色主题**：长时间运营后台标配，应加 `light/dark/system` 三态切换（专家规范默认要求）。
- 表单 3 列网格在 920px 直接塌成 1 列，卡片编辑器字段多时会拉得很长，缺「平板两栏」中间档。

---

## 七、快速见效清单（低成本高收益，建议先做）

| # | 改法 | 收益 | 成本 |
|---|------|------|------|
| 1 | 落地页改为「模板」，模型收进系统配置 | 消除"一进来是密钥表"的错愕 | 极低 |
| 2 | `status` 数字 → 上架/下架开关 + 状态筛选 | 消除"1=上架?"记忆负担 | 低 |
| 3 | 表单字段分组 + 高级折叠 | 编辑器可读性翻倍 | 中 |
| 4 | `window.confirm` → 统一 Dialog + 危险操作输入确认 | 减少误删 | 低 |
| 5 | 全局 Toast | 操作有反馈 | 低 |
| 6 | 全列表加搜索 + 状态筛选 | 找数据不再翻页 | 中 |
| 7 | 术语改名（卡片→模板、标签→分组、星光→积分、夯/拉→注释或隐藏） | 运营理解成本归零 | 低 |
| 8 | 右侧实时预览（复用 web-app 的 template-visual） | 改了有把握 | 中 |

---

## 八、优先级总览

```text
P0（体验断点，影响使用意愿）
├─ 落地页错误、状态裸数字、无搜索、window.confirm 滥用、无 Toast
P1（效率提升，影响运营产能）
├─ 表单分组折叠、术语改名、分页升级、列分层、批量操作、预览
P2（专业化，影响规模化）
├─ 版本/灰度、质量评测、暗色主题、用户详情、打包下载
```

这些体验优化可以和上一轮的「阶段 2 体验与数据重构」合并推进，不必与安全止血、模块补齐冲突。
