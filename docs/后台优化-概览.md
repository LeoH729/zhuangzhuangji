# 后台优化 · 概览

> 详细方案见同目录《后台架构优化方案.md》。本文件为 3 分钟速读版。

## 一句话结论

后台「能用但地基不稳」：存在 **4 个 P0 安全漏洞**，且仅覆盖「配置管理」，缺失运营、监控、商业化、数据四大能力。

## 4 个必须先修的安全漏洞

1. **模型 API Key 泄露给客户端**（`modelConfig` 的 `getList/getDetail` 返回含 `api_key`）
2. **模板/模型接口无鉴权可增删改**（`modelConfig`/`featureConfig` 的写操作）
3. **积分可无限免费充值**（`points` 的 `recharge` 无支付校验）
4. **开放注册 + 空表可自封超管**（登录页注册入口 + `bootstrapAdmin`）

## 能力差距（绿=已有，蓝=部分，橙=缺失）

- 🟩 已有：素材中心（图片模块）
- 🟦 部分：模板中心、模型与路由、用户与权限
- 🟧 缺失：运营概览、任务故障中心、订单与退款、数据分析、内容安全、审计日志

## 核心改造方向

- 止血 → 补模块（Dashboard/任务中心/订单/反馈/审计）→ 体验与数据重构（路由/搜索/RBAC/分页/账本）→ 产品化（模板版本/灰度/评测）
- 前端拆分单文件巨石，云函数按领域模块化，数据底座三端共享（统一 userId、模板版本、credit_ledger、audit_logs）

## 建议节奏

阶段0（1天）止血 → 阶段1（1~2周）补关键模块 → 阶段2（2~3周）体验与数据 → 阶段3 持续产品化。**不一次性重写，逐模块替换。**
