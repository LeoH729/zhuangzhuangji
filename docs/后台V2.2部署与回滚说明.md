# AI 造梦馆运营后台 V2.2 部署与回滚说明

## 发布范围

- 云环境：`cloudbase-5gmfinom29f48930`
- 云函数：`adminApi`、`featureConfig`、`adminAnalytics`、`aiGenerate`
- 静态站点：`admin-web/dist` → `/admin/V2/`
- 管理后台：`https://makedream-admin.supersolo.tech/admin/V2/`
- 本轮不发布小程序；旧入口 `/admin/` 保持不变。

## 本轮能力

- 模板中心精简编辑与一键「发布到小程序」（去掉版本说明 / 5 组测试门禁 / 定时发布）
- 推荐位按专区 + 角标独立排序（`saveRecommendationOrder` / `migrateRecommendationOrderV22`）
- 图片中心区分用户图片与运营图片，保护被引用素材
- 运营首页：业务日期 + 近 7/15/30 天趋势
- 评价计数事务回写兼容字段（`hang_count` / `user_hang_count` 等）

## 发布前检查

1. `npm test`（V2/V2.1/V2.2 契约全部通过）
2. `node --check cloudfunctions/adminApi/index.js` 等关键函数
3. `npm --prefix admin-web run build`
4. 备份线上 `/admin/V2/`（`tcb hosting download /admin/V2 <backup> --dir`）

## 发布顺序（已执行于 2026-08-19）

1. 部署 `adminApi`、`featureConfig`、`adminAnalytics`、`aiGenerate`（`--force`，云端安装依赖）
2. 部署静态资源：`tcb hosting deploy ./admin-web/dist /admin/V2 --yes`
3. 删除旧 hash 资源（`index-BnLTQ9LD.js` / `index-CgZzdf1t.css`）
4. 验证自定义域名 HTML 指向 `index-D-yyEnEQ.js`

## 可选数据迁移

超级管理员在后台或云函数调用：

- `migrateRecommendationOrderV22`：默认 `dryRun=true`，对账通过后 `dryRun=false`
- `rebuildTemplateRatingCounts`：需要重建评价计数时执行

## 回滚

- 页面：将 `.tmp/hosting-backup-v22-pre-*` 重新部署到 `/admin/V2/`
- 云函数：切回上一稳定版本，或从发布前函数代码包恢复
- 推荐位迁移只写 `placements.sort_order` 与 `recommendationOrderMigration`，不删除旧字段

## 生产冒烟清单

- 打开 `https://makedream-admin.supersolo.tech/admin/V2/`，标题为「AI 造梦馆运营后台」
- 导航顺序：模板中心 → 推荐位与排序 → 分类管理 → 图片中心
- 模板：保存草稿 / 发布到小程序；未配置展示位置时发布检查失败
- 推荐位：拖拽排序后刷新仍保持
- 图片中心：用户图片 / 运营图片分区可见
- 运营首页：可见业务日期与近 15 天趋势入口
