# AI 造梦后台 V2.0 产品方案

## 1. 产品目标

后台 V2 是面向模板生产、运营分析、任务治理、用户和商业管理的统一运营系统。一期优先服务小程序，数据字段和接口不绑定微信端，为网站后续接入保留 `app_version`、`session_id`、`source_page`和渠道字段。

核心目标：

- UI 不再混用“卡片、功能、积分、蛋”等旧业务称呼。
- 模板具备草稿、测试、发布、下线、版本和回滚闭环。
- 运营首页统一展示用户、模板、渠道和生成性能数据。
- 高风险操作可追溯，密钥、星光和管理权限不从公网绕过。
- 兼容读取旧表与旧字段，V2 新增写入使用统一领域名。

## 2. 信息架构

```text
运营首页
模板运营
├─ 模板中心
├─ 分类管理
├─ 素材中心
└─ 推荐位与排序
业务运营
├─ 生成任务
├─ 用户管理
├─ 反馈与投诉
└─ 订单与星光
系统管理
├─ 模型与路由
├─ 审计日志
├─ 管理员与权限
└─ 系统配置
```

当前静态托管采用 hash URL，例如 `#/templates`，以保证刷新和深链不依赖服务端 SPA 回退。后续切换到支持 history fallback 的托管服务后，可无损替换为 `/templates` 等路径。

## 3. 模板生产流程

1. 新建模板，填写名称、类型、分类、展示专区和业务说明。
2. 保存草稿并取得稳定的模板 ID。
3. 配置用户输入字段、提示词变量、校验规则和错误文案。
4. 配置输出比例、数量、高清能力和星光消耗。
5. 选择主能力路由和兜底路由。服务商只在高级配置中展示。
6. 至少运行 5 组后台测试。每组记录模型、兜底是否启用、目标比例、状态、耗时、错误和结果。
7. 发布前通过模型可用性、素材、展示位置、星光、提示词和测试数量门禁。
8. 填写必填版本说明后发布。系统写入不可变更的 `template_versions` 快照和审计日志。
9. 上线后从运营首页和生成任务观察成功率、使用率与失败原因。异常时下线或回滚到任一已发布版本。

状态机：

```text
draft 草稿 → testing 测试中 → ready 可发布 → published 已发布 → offline 已下线
```

兼容投影：`status=1` 对应 `published`，`status=0` 对应草稿或下线。

## 4. 运营首页

日期支持今日、昨日、近 7 天、近 30 天和自定义，以 Asia/Shanghai 自然日计算。今日标记“动态”，昨日及之前标记“已定稿”。

页面顺序：用户指标卡、用户趋势、模板整体使用率、模板详情访问 Top 10、模板使用率 Top 10、高清图保存率 Top 10、渠道使用率、生图成功率与失败原因、数据新鲜度和缺失埋点。分母为 0 返回 `null`，UI 展示“—”。

## 5. 角色与权限

| 角色 | 可见范围 |
|---|---|
| `super_admin` | 全部模块，可管理管理员和角色 |
| `admin` | 全部业务模块，不可管理管理员 |
| `template_editor` | 运营首页、模板、分类、素材和模型路由 |
| `operator` | 运营首页、生成任务、用户和反馈 |
| `finance` | 运营首页、用户、订单与星光 |
| `readonly_analyst` | 仅运营首页 |

数据看板权限领域名固定为 `analytics.read`。删除、下线、回滚和星光调整记录审计日志，API Key、密码和 Token 在日志中自动脱敏。

## 6. 交互和反馈基线

- 请求超过 300ms 显示加载并阻止重复提交。
- 成功显示明确状态，失败展示中文原因和可执行建议。
- 列表统一分页、刷新和筛选；空数据、缺埋点、无权限和网络失败使用不同文案。
- 删除和回滚需输入模板名称，下线需二次确认。
- 状态不仅依赖颜色，同时显示文字。

## 7. 迁移与上线

1. 轮换历史密钥，配置 `BOOTSTRAP_TOKEN`、`INTERNAL_FUNCTION_TOKEN`、后台 Web 访问凭据和支付环境变量。
2. 部署 `analyticsIngest`、`analyticsAggregate`、`adminAnalytics`和新 `adminApi`。
3. 创建数据库集合和索引，验证 5 分钟定时汇总。
4. 先发布小程序双写埋点，再灰度切换后台首页。
5. 将 `ai_features` 的真实模板作为 V1 快照迁移，至少选取 10 个模板做 UAT。
6. 旧后台保留一个版本周期的只读入口。切换失败时回滚 Web 入口，不回退已接收的事件数据。

模板迁移使用超级管理员接口 `migrateTemplatesV2`。默认 `dryRun=true`，对账通过后传入 `dryRun=false`。它会跳过已有版本或已迁移的模板，因此可重复执行。如需撤销本次自动迁移，调用 `rollbackTemplatesV2Migration`并传入 `confirm=ROLLBACK_V2_BOOTSTRAP`；该操作只删除带 `migrationTag=v2_bootstrap` 的快照，不删除人工发布版本。

## 8. 本次实现边界

已实现 V2 导航、运营首页、精确保存埋点、渠道归因、事件双写、日汇总、任务/订单/反馈/审计页、角色权限、模板测试门禁、直接或定时发布、版本快照、回滚和上线后 24 小时观察卡。可视化输入编排在原有动态字段表单上完成三栏化增强，并保留旧数据兼容投影。
